# GovTech Camp — Кейс 1: Нагрузка на стационары и очереди на госпитализацию

AI/Data-система мониторинга и прогнозирования потоков пациентов в стационарах Казахстана:
аналитика очередей и отказов, прогноз времени ожидания госпитализации, прогноз суточной
нагрузки стационаров и детектор аномальных всплесков — с объяснением каждого прогноза.

Данные: открытые наборы Министерства здравоохранения РК (ИС БГ, ЭРСБ) через портал
ashyq.data.gov.kz, выгрузка 2025 Q1.

## Что делает решение

- **Аналитика** — направления на плановую госпитализацию (767 тыс. событий), очередь
  (765 тыс. пациентов, 1 406 стационаров, ~70 профилей коек), отказы приёмного покоя
  (1.5 млн событий, 20 регионов), пролеченные случаи в разрезе медорганизаций (ЭРСБ).
- **Прогноз времени ожидания** — для конкретного направления (стационар + профиль коек +
  группа МКБ-10 + регион + …) модель предсказывает через сколько дней пациент будет
  госпитализирован и показывает, какие факторы и на сколько дней повлияли (SHAP).
- **Прогноз нагрузки стационара** — суточные госпитализации по паре (стационар, профиль
  коек) на 14 дней вперёд с интервалом неопределённости.
- **Детектор всплесков** — дни с аномальным числом отказов по региону относительно
  скользящей медианы (z ≥ 3.5 по MAD).

## Быстрый старт

**Шаг 1. Скачать данные.** Скачать датасет по ссылке: (https://drive.google.com/drive/folders/1k5UT2Xp3ErPkfnLg6E0BGANqGsC1yzKm?usp=sharing).
Создать в корне проекта папку `датасет/` и поместить туда все скачанные CSV-файлы
(состав файлов — см. раздел «Данные» ниже).

**Шаг 2. Установить зависимости и запустить:**

```bash
pip install -r requirements.txt
streamlit run app/main.py
```

Приложение запустится на http://localhost:8501. Для остановки — `Ctrl+C`.

Первый запуск построит parquet-кэш сырых CSV (~40 с) и обучит модели (~15 с); последующие
запуски стартуют мгновенно из кэшей. Сырые CSV лежат в `датасет/` (путь настраивается
в `src/config.py`). Принудительное переобучение: удалить файлы из `models/` и перезапустить.

## Архитектура

```
app/main.py          — Streamlit-приложение: обзор, очереди, отказы, ЭРСБ, прогнозы
src/config.py        — пути и параметры данных
src/loaders.py       — загрузка CSV → parquet-кэш, нормализация, целевые признаки
src/regions.py       — регион по названию МО (парсер) + справочник кодов регионов
src/model_waiting.py — модель №1: прогноз времени ожидания (LightGBM + SHAP)
src/model_load.py    — модель №2: прогноз суточной нагрузки (лаги, рекурсивный прогноз)
src/anomalies.py     — детектор всплесков отказов (медиана + MAD)
models/              — обученные артефакты (нативный формат LightGBM + JSON)
cache/               — parquet-кэш сырых данных (создаётся автоматически)
датасет/             — сырые выгрузки портала (не изменять)
.streamlit/          — тема оформления (светлая/тёмная — переключатель в приложении)
```

Пайплайн: CSV → нормализация (категории, ISO-даты) → parquet-кэш → признаковое
пространство → LightGBM → артефакт (booster + JSON-метаданные) → Streamlit.
Валидация во всех моделях только по времени (train на ранних датах, test на поздних) —
утечка будущего исключена.

## Модели и метрики

**№1. Время ожидания госпитализации** (для госпитализированных, срок 0–90 дней;
13.6% записей с артефактом выгрузки исключены).
Признаки: стационар, профиль коек, группа МКБ-10, регион, тип населённого пункта, цель
направления, источник финансирования, месяц, день недели.
Валидация: обучение янв–фев (395 122), проверка март (163 448).

| Метрика | Значение |
|---|---|
| MAE | 4.8 дня |
| Медианная абсолютная ошибка | 1.8 дня |
| Прогнозы с точностью ±1 день | 37% |
| WAPE | 68% |

WAPE высок из-за природы данных: у большинства пациентов ожидание близко к нулю, и
промах в 2–3 дня на них даёт большой относительный вклад. Для планирования важен порядок
величины («через несколько дней» или «через месяц») — модель различает его уверенно.

**№2. Нагрузка стационара** (госпитализации по дням, пары стационар × профиль коек).
Признаки: лаги 1/7/14 дней, скользящее среднее 7 дней, среднее серии (по обучающему
периоду), день недели и месяца. Валидация: обучение до 18 марта (84 252 паро-дней),
проверка 18–31 марта (13 837).

| Метрика | Значение |
|---|---|
| WAPE | 48% |
| MAE | 1.4 пациента/день |

Прогноз рекурсивный на 14 дней от последней даты выгрузки; лента — ±1.28 σ ошибок
(~80% интервал). История ограничена январём–мартом 2025: даты госпитализаций в выгрузке
размазаны по 2024–2026 (записи, обновлённые после окна экспорта).

**Детектор аномалий.** Базовая линия — скользящая медиана предыдущих 14 дней, разброс —
MAD (устойчив к выбросам), всплеск: z ≥ 3.5 только вверх. За Q1 2025 найдено 60 всплесков.

## Известные особенности данных

- 13.6% направлений имеют `hospitalization_dt` раньше `registration_dt` — артефакт
  выгрузки; исключены из модели времени ожидания.
- `hospitalization_dt` размазан по 2024–2026 — модель нагрузки использует только Q1 2025.
- ЭРСБ — кумулятивный снимок без разбивки по периодам: сравнение организаций возможно,
  динамика — нет.
- **ЕИП (лабораторные исследования) отсутствует** в выданных материалах — подзадача
  «прогноз нагрузки на лаборатории» не реализуема на этих данных.
- Регион восстанавливается по названию организации: покрытие 72% (направления) и 44%
  (ЭРСБ); у частных клиник регион в названии не указан. Коды регионов очереди — KATO 2023;
  коды 33 (Жетісу) и 62 (Ұлытау) уточнены вручную: голосование по регионам больниц
  смещено маятниковой госпитализацией в соседние области.

## Ограничения и принципы

- Прогнозы — **поддержка решения** (human-in-the-loop): финальное решение за специалистом;
  система не выдаёт диагнозов и рекомендаций пациентам.
- Месяцы апрель–июнь в прогнозе ожидания — экстраполяция за пределы обучающего периода.
- Персональные данные в используемых наборах отсутствуют (агрегаты и обезличенные события).
- Каждый прогноз сопровождается объяснением факторов и метриками качества модели.
